# Project Specification — Algerian E-Commerce Platform
**Document for AI Coding Agent — Phase 1: Admin Dashboard**

---

## Project Overview

Build a full-stack, production-ready e-commerce platform for an Algerian clothing and book store. The platform has three dashboards sharing a single Supabase backend:

- **Admin Dashboard** — full management control
- **Khadem (Employee) Dashboard** — daily in-store sales
- **Client Storefront** — public-facing online store

**Current task: Build Phase 1 — Admin Dashboard only.**

- No colored card borders
- No emoji — Lucide React icons exclusively
- No icon-in-colored-circle patterns
- Clean, minimal, professional

```css

--font-display: 'General Sans', 'Inter', sans-serif;

```

### Component Rules

- **Buttons:** Solid bg for primary, white+border for secondary, ghost for tertiary
- **Tables:** Clean borders, alternating row hover (#f9f9f9), sticky header
- **Cards:** White bg, 1px border (#e5e5e5), 8px radius, subtle shadow
- **Inputs:** White bg, 1px border, focus ring uses teal
- **Badges:** Small, rounded-full, use semantic colors (success/warning/error)
- **Modals:** Centered overlay, white card, always have title + close button
- **Empty states:** Icon (Lucide) + title + description + action button — never just "No data"
- **Skeleton loaders:** On every data-loading view before content arrives
- **Mobile-first:** All pages fully responsive, 44px minimum touch targets

## Database Schema (Already Migrated to Supabase)

The Supabase database is already set up with the following tables:

```
profiles               — users with roles: admin | khadem | client
categories             — product categories (e.g. Hommes, Femmes, Enfants, Livres)
models                 — product models per category (e.g. Chemise, Jilbab)
articles               — products with barcode, base_price, is_published, low_stock_threshold
article_photos         — multiple photos per article (position-ordered)
article_sizes          — sizes per article (size_label, is_standard, price_override nullable)
article_size_colors    — color+quantity per size (color_name, color_hex, quantity)
promotions             — discount coupons (code, type: percent|fixed, value, min_order, max_uses)
daily_sessions         — khadem daily session (one per khadem per day, unique constraint)
bons                   — sales receipts (soft-deletable, total_price stored)
bon_items              — line items per bon (size_id, color_id, quantity, unit_price, discount_amount)
orders                 — online orders (COD only, status flow: pending→confirmed→shipped→delivered|cancelled)
order_items            — line items per order
purchase_vouchers      — stock purchase vouchers (created by admin)
purchase_voucher_items — line items per voucher (purchase_price + sale_price, auto-increments stock)
store_settings         — single-row store config (one row already seeded)
delivery_fees          — per-wilaya delivery pricing
```

**Key relationships:**
- `article_sizes.price_override` — nullable; if NULL, use `articles.base_price`
- `daily_sessions.total_recette` — NOT stored; always compute as `SUM(bons.total_price) WHERE is_deleted = false`
- `orders.client_id` — nullable FK to profiles (guests can order without account)
- `orders.payment` — COD only (no payment gateway needed)
- Stock is managed via DB triggers automatically:
  - bon_item INSERT → deducts `article_size_colors.quantity`
  - bon soft-delete → restores stock
  - order status pending→confirmed → deducts stock
  - order status confirmed→cancelled → restores stock
  - purchase_voucher_item INSERT → adds stock

**Supabase TypeScript types** are generated via:
```bash
npx supabase gen types typescript --project-id YOUR_PROJECT_ID > src/types/database.types.ts
```

Use these types throughout — never use `any`.

**RLS is fully configured.** Admin role has full access to all tables.

## Supabase Client Setup

```typescript

import type { Database } from '@/types/database.types'

export const createClient = () =>
  createBrowserClient<Database>(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!
  )
```

```typescript
// src/lib/supabase/server.ts
import { createServerClient } from '@supabase/ssr'
import { cookies } from 'next/headers'
import type { Database } from '@/types/database.types'

export const createClient = () => {
  const cookieStore = cookies()
  return createServerClient<Database>(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() { return cookieStore.getAll() },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value, options }) =>
            cookieStore.set(name, value, options))
        },
      },
    }
  )
}
```

```typescript
// middleware.ts
import { createServerClient } from '@supabase/ssr'
import { NextResponse, type NextRequest } from 'next/server'

export async function middleware(request: NextRequest) {
  let supabaseResponse = NextResponse.next({ request })
  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() { return request.cookies.getAll() },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) => request.cookies.set(name, value))
          supabaseResponse = NextResponse.next({ request })
          cookiesToSet.forEach(({ name, value, options }) =>
            supabaseResponse.cookies.set(name, value, options))
        },
      },
    }
  )

  const { data: { user } } = await supabase.auth.getUser()

  if (request.nextUrl.pathname.startsWith('/admin')) {
    if (!user) {
      return NextResponse.redirect(new URL('/auth/login', request.url))
    }
    const { data: profile } = await supabase
      .from('profiles')
      .select('role')
      .eq('id', user.id)
      .single()
    if (!profile || profile.role !== 'admin') {
      return NextResponse.redirect(new URL('/auth/login', request.url))
    }
  }

  return supabaseResponse
}

export const config = {
  matcher: ['/admin/:path*', '/khadem/:path*'],
}
```

### 2. Products (`/admin/products`)

**List view:**
- Table: photo thumbnail, title, category, model, charika, base_price, stock status badge, barcode, actions
- Smart debounced search (300ms) across: title, barcode, charika, category name, model name
- Filter chips: by category, by model, by stock status, by published status
- URL-synced filters (browser back/forward works)
- Pagination (20 per page)
- Bulk actions: bulk delete, bulk publish/unpublish
- Empty state with "Add Product" CTA

**Add/Edit Product modal or page:**

Form fields:
1. Title (required)
2. Description (textarea)
3. Category (dropdown — fetches from categories table)
4. Model (dropdown — filters by selected category)
5. Brand/Charika (text input)
6. Base Price (number, required)
7. Is Published toggle
8. Low stock threshold (number, default 5)
9. Photos upload:
   - Multiple files, drag-to-reorder (position saved to article_photos)
   - Client-side compression via browser-image-compression before upload
   - Upload to Supabase Storage bucket: article-photos
   - Display uploaded thumbnails with delete button
10. Sizes section (dynamic):
    - Add size button → opens inline form: size_label + is_standard toggle + price_override (optional)
    - Each size shows a collapsible color section
11. Colors per size (dynamic):
    - Add color button → color_name + color_hex (color picker) + quantity
    - Show color swatch preview
12. Barcode:
    - Auto-generated Code128 barcode on article creation using jsbarcode
    - Stored as string in articles.barcode
    - Displayed as scannable barcode image
    - Print button → generates PDF label (jsPDF): article name + size + price + barcode graphic

Validation (zod):
- title: required, min 2 chars
- base_price: required, >= 0
- category_id: required
- At least one size required
- Each size must have at least one color with quantity >= 0

Optimistic UI: add article appears immediately in list, rolls back on error.

## Cross-Cutting Technical Requirements

### Data Fetching Strategy

- **Server Components** for initial data load (SEO + performance)
- **Client Components** only for interactive parts (search, forms, modals)
- **Optimistic UI** on all mutations — never show loading spinners on user-triggered actions
- **Skeleton loaders** on all server-fetched views

### Forms

All forms use `react-hook-form` + `zod`:

```typescript
// Example zod schema
const articleSchema = z.object({
  title: z.string().min(2, 'Title is required'),
  base_price: z.number().min(0, 'Price must be positive'),
  category_id: z.string().uuid('Select a category'),
  model_id: z.string().uuid().optional(),
  charika: z.string().optional(),
  description: z.string().optional(),
  is_published: z.boolean().default(true),
  low_stock_threshold: z.number().int().min(0).default(5),
})
```

### Smart Filtering (All List Views)

Pattern to implement on every list page:
- Debounced search input (300ms) — searches all relevant text fields simultaneously
- Filter chips with individual dismiss buttons
- URL state sync using `useSearchParams` + `router.replace`
- Empty state component when no results match
- "Clear all filters" button when filters are active

### Error Handling

- Form validation errors: inline, next to field, red color, specific message
- API errors: toast notification (top-right, 4s duration)
- Empty states: always designed with icon + message + action
- Never show raw error codes to users

### Barcode Generation

```typescript
import JsBarcode from 'jsbarcode'

// Generate Code128 barcode string (internal use only)
function generateBarcode(): string {
  const timestamp = Date.now().toString()
  const random = Math.random().toString(36).substring(2, 7).toUpperCase()
  return `ART-${timestamp}-${random}`
}

// Render to canvas for display
function renderBarcode(canvas: HTMLCanvasElement, value: string) {
  JsBarcode(canvas, value, {
    format: 'CODE128',
    width: 2,
    height: 60,
    displayValue: true,
    fontSize: 12,
    margin: 10,
  })
}
```

### Image Upload Pattern

```typescript
import imageCompression from 'browser-image-compression'
import { createClient } from '@/lib/supabase/client'

async function uploadArticlePhoto(file: File, articleId: string) {
  const compressed = await imageCompression(file, {
    maxSizeMB: 0.5,
    maxWidthOrHeight: 1200,
    useWebWorker: true,
  })
  const supabase = createClient()
  const filename = `${articleId}/${Date.now()}-${file.name}`
  const { data, error } = await supabase.storage
    .from('article-photos')
    .upload(filename, compressed)
  if (error) throw error
  const { data: { publicUrl } } = supabase.storage
    .from('article-photos')
    .getPublicUrl(filename)
  return publicUrl
}
```
